# 3.5-A: Claude vs 8b vs 14b Comparison

**Date:** 2026-02-19
**Models tested:** qwen3:8b (my-persona-designer-q3), qwen3:14b (direct), Claude Haiku 4.5 (no web search)
**Test cases:** 3 representative cases (Axon 4.9, Research agent, Brainstorm)

---

## Case 1: Axon Framework 4.9 (Hard dependency-chain reasoning)

### Temperature & Domain
| Model | Temp | Domain |
|-------|------|--------|
| 8b | 0.3 | code |
| 14b | 0.3 | code |
| Haiku | 0.3 | code |
All correct (Axon patterns are architectural law, not creative).

### Jakarta/javax Namespace
| Model | Constraint | Correct? |
|-------|-----------|----------|
| 8b | "MUST use jakarta.*" | ✓ Correct (Axon 4.9 → Spring Boot 3.x) |
| 14b | (omitted) | ✓ Safe (avoided potential error) |
| Haiku | "MUST use Jakarta EE (jakarta.*, not javax.*)" | ✓ Correct + explicit |

**Finding:** 8b got it right (though we initially thought it wrong). Haiku provided the most explicit constraint with version reasoning.

### Framework-Specific Constraints
| Model | Key Patterns |
|-------|--------------|
| 8b | @AggregateRoot, @CommandHandler, @EventSourcingHandler, Axon 4.9+ only |
| 14b | @EventSourcingHandler, @EventHandler, @SagaHandler, CommandGateway config |
| Haiku | CQRS separation, async patterns, eventual consistency, snapshot config |

**Finding:** Haiku generated the most **sophisticated** constraints (eventual consistency, snapshot management). Local models stay at pattern level; Haiku adds architectural reasoning.

## Case 2: Python Research Agent (Domain-specific knowledge)

### Temperature & Domain
| Model | Temp | Domain |
|-------|------|--------|
| 8b | 0.1 | reasoning |
| 14b | 0.1 | reasoning |
| Haiku | 0.3 | reasoning |

Haiku chose 0.3 (slightly creative) vs 0.1 (strict). Both are defensible.

### Bibliography Approach
| Model | Approach |
|-------|----------|
| 8b | arXiv API, BibTeX format, dedup, language preservation |
| 14b | arXiv/PyPI APIs, BibTeX, metadata validation, deterministic summarization |
| Haiku | JSON output, URL validation, structured sections, confidence scores |

**Finding:** Haiku took a **different philosophy** — no external APIs mentioned, focus on testing (mock data, validation). This is arguably better for a local agent (fewer external dependencies), but assumes the researcher won't actually fetch papers. 8b/14b assume real API integration.

### Constraints Quality
- **8b/14b:** Action-oriented (fetch, output, validate)
- **Haiku:** Structure-oriented (organize, validate, score confidence)

Haiku's constraints are more testable but less aligned with "fetches papers" intent.

## Case 3: Creative Brainstorm (Abstract intent → concrete constraints)

### Temperature (KEY DIFFERENCE)
| Model | Temp | Reasoning |
|-------|------|-----------|
| 8b | 0.7 | Standard for creative |
| 14b | 0.7 | Standard for creative |
| Haiku | **0.9** | Max temperature — understood "unconventional" deeply |

**Finding:** Haiku **escalated temperature** to 0.9, showing better understanding of "avoids filtering or self-censorship" → needs highest randomness.

### Constraints Quality
| Model | Key Constraints |
|-------|-----------------|
| 8b | 5+ ideas, no filtering, multi-domain, novelty > practicality |
| 14b | No filtering, originality > conventional, 3+ variations, no feasibility |
| Haiku | 5-10 ideas, avoid disclaimers, embrace absurd, vivid language, equal enthusiasm |

**Finding:** Haiku went **deeper on anti-patterns** ("avoid safety disclaimers", "no caveats") and added style guidance ("vivid, evocative language"). This shows nuanced understanding of creative intent.

## Summary: When Each Model Excels

### 8b (qwen3:8b persona)
**Strengths:**
- Good pattern recognition (Axon annotations)
- Solid domain knowledge (arXiv, BibTeX)
- Efficient (~10-20s per case)

**Weaknesses:**
- Doesn't escalate to architectural reasoning (eventual consistency, snapshots)
- Doesn't surface anti-patterns (disclaimers, caveats)
- Temperature choices are conservative

### 14b (qwen3:14b direct)
**Strengths:**
- More detailed constraints (7+ per case)
- Includes implementation details (snapshot config, saga patterns)
- Similar to 8b but more verbose

**Weaknesses:**
- Slower (3x 8b, limited 4K context)
- Still doesn't capture Haiku's architectural sophistication
- Avoids potentially difficult reasoning (jakarta/javax) rather than solving it

### Claude Haiku (no web search)
**Strengths:**
- **Best understanding of abstract intent** (temperature escalation)
- **Anti-pattern thinking** (avoid disclaimers, avoid "caveats")
- Architectural reasoning (eventual consistency, snapshots)
- Most sophisticated persona spec quality

**Weaknesses:**
- Different philosophy on some domains (Research agent: testing-focused vs API-focused)
- Slower response (~3.4s per case, but overall session time matters)

---

## Recommendation for 3.5-A Closure

1. **8b is production-ready** for persona generation at current quality level
2. **14b shows no clear improvement** over 8b (longer, similar quality, context-limited)
3. **Claude Haiku is best-in-class** for understanding subtle intent and generating sophisticated constraints

**Action:**
- Keep 8b as default (`my-persona-designer-q3`)
- Document that `qwen3:14b` is not worth the trade-off
- Note that Claude Haiku could be used as a "second opinion" tool for complex personas
- Consider updating `build-persona.py` to suggest clarifying questions when intent is vague (learned from Haiku's success)

---

## Notes for Layer 4 (Evaluation Framework)

The fact that Haiku excels at **anti-pattern thinking** and **intent understanding** suggests that the Layer 4 evaluator should score personas on:
1. **Anti-pattern coverage** (e.g., "avoid disclaimers" for creative personas)
2. **Architectural sophistication** (eventual consistency, snapshots, etc.)
3. **Intent alignment** (how well does temperature match intent?)

This will help identify which models are best suited for different persona types.
